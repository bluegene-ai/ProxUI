# ProxUI 简体中文汉化（zh-CN）

本仓库是 [greenlogles/ProxUI](https://github.com/greenlogles/ProxUI) 的汉化分支。汉化以
**可重复套用的工具链**形式实现，而不是一次性手改——上游更新后可以重新跑脚本再套一遍。

## 汉化方式

没有引入运行时翻译层，也没有改 `app.py`。文案在**源码层面**被替换成中文，因此：

- 零运行时开销、零额外请求；
- 不依赖 DOM 二次扫描，不存在"动态内容漏翻"的匹配脆弱性；
- 后端日志与异常信息保持英文，便于搜索排错。

替换只发生在三种精确位置上，避免误伤结构：

| 位置 | 规则 |
|---|---|
| HTML 文本节点 `>文本<` | 整节点归一化后精确匹配 |
| 静态属性 `title/placeholder/aria-label/alt` | 仅匹配非 Alpine 绑定（跳过 `:attr`、`x-attr`、`@attr`） |
| JS 字符串字面量 `'…'` `"…"` `` `…` `` | 整字面量精确匹配，保留原引号类型 |

含 Jinja 表达式（`{{ }}` / `{% %}`）的节点**不参与**整节点替换，改用 `special.json` /
`special_js.json` 中的长片段替换，确保 `{{ }}` 与 `${ }` 占位符原样保留。

## 目录结构

```
i18n/
├── extract.py                 提取待译文案 -> candidates.json
├── apply.py                   应用词典（支持 --check 干跑）
├── build_special.py           由骨架生成 special.json
├── verify_render.py           Flask test client 全路由渲染校验
├── browser_check.py           Chromium 实跑（控制台错误 / 可见文本）
└── dict/
    ├── html_text_a.json       模板可见文本（A–N，342 条）
    ├── html_text_b.json       模板可见文本（N–Z 及句尾片段，346 条）
    ├── html_attr.json         静态属性文案（64 条）
    ├── html_labels.json       单词标签（按钮/表头/统计卡，153 条）
    ├── js_string_a.json       外部 JS 与内联脚本字面量（A–F，144 条）
    ├── js_string_b.json       外部 JS 与内联脚本字面量（F–Z，162 条）
    ├── special.json           含 {{ }} 的插值文案（32 条）
    ├── special_base.json      结构性字符串：导航数组、<html lang>、各页 <title>（32 条）
    ├── special_js.json        含 ${ } 的插值文案与动态拼接 DOM 文案（102 条）
    └── special.skeleton.json  插值节点的精确原文骨架（供 build_special.py 使用）
```

词典可用条目合计 **1377 条**（不含骨架文件）。

## 实测覆盖

从干净的上游提交（`64bb45d`）重跑 `python3 i18n/apply.py`，实际替换点：

| 类型 | 替换数 |
|---|---|
| HTML 文本节点 | 1138 |
| 静态属性 | 101 |
| JS 字符串字面量 | 412 |
| 插值 / 结构性片段 | 172 |
| **合计** | **1823** |

词典对提取结果的覆盖率（`apply.py --check` 输出）：

| 分桶 | 覆盖 | 比例 |
|---|---|---|
| 模板文本 `html_text` | 835 / 853 | 97.9% |
| 静态属性 `html_attr` | 82 / 103 | 79.6% |
| JS 字面量 `js_string` | 306 / 456 | 67.1% |
| **合计** | **1223 / 1412** | **86.6%** |

未覆盖的部分并非遗漏：`js_string` 那 150 条绝大多数是 **CSS 类名、API 路径、
`firewall=1` 之类配置串**，本就不应翻译；`html_attr` 的缺口是路径与示例值
（`/dev/dri/renderD128`、`example.com`、`ssh-rsa AAAA...`）。

英文长句（连续 ≥3 个英文单词）消除率，口径为对比 `HEAD` 与工作区：

| 范围 | 汉化前 | 汉化后 | 消除 |
|---|---|---|---|
| `templates/`（文本节点 + 内联脚本） | 528 | 53 | 90.0% |
| `static/js/` | 136 | 3 | 97.8% |
| **合计** | **664** | **56** | **91.6%** |

剩余部分构成：

- **可见文本节点只剩 3 处**：2 处是"Proxmox Backup Server 目标会忽略此项…"这类
  含英文产品名的中文句子，1 处是 JS 源码注释（非用户可见）；
- `templates/` 那 53 的其余部分全部是 **CSS 类名**（`form-control form-control-sm`、
  `btn btn-sm btn-outline-danger` 等）与 `firewall=1` 这类配置串——**本就不应翻译**。

## 验证手段

**关键原则：所有结论都对照基线提交 `64bb45d` 比对，而不是孤立地"跑通了"。**
同样的命令在原版与汉化版各跑一次，只承认"两边一致"或"差异可解释"。

### 一、静态检查（不需要 Proxmox）

1. **Jinja 编译**：23 个模板全部 `Environment.get_template()` 通过，0 失败；
2. **JS 语法**：14 个 `static/js/*.js` 全部 `node --check` 通过；
3. **内联脚本回归**：逐块比对"改前可编译、改后不可编译"，0 回归；
4. **定界符守恒**：逐文件比对 `{{ }} {% %}` 与 `<script>` 计数，全部一致；
5. **标签开闭平衡**：30 类标签的 `<x` 与 `</x>` 计数逐文件一致；
6. **引号安全**：译文中的 ASCII 引号逐条审计——`js_string_*` 中**零条**含单引号，
   因此插入单引号字面量不会破坏语法；含双引号的 4 条均位于 Jinja 表达式、
   HTML 属性或反引号模板内。

### 二、运行时渲染（不需要 Proxmox，需要 Flask）

`python3 i18n/verify_render.py` 会启动真实 Flask 应用、注入伪造的 Proxmox 对象，
然后请求全部页面路由。与原版对照结果：

| 指标 | 基线 `64bb45d` | 汉化后 |
|---|---|---|
| 返回 200 的页面 | 15 / 17 | **15 / 17** |
| 状态码与异常 | — | **逐路由完全一致** |
| 页面含中文 | 0 | 15 |
| 标签数 / id 集合 / class 集合 | 基准 | **逐页完全相同** |

即：页面结构、路由行为、异常分布均未改变，只有文字变了。
两个非 200 的路由（`/networks` 抛 JSON 序列化异常、`/vm/.../edit` 302 重定向）
在**原版上表现完全相同**，属于该桩环境的固有限制，与汉化无关。

### 三、功能语义审计

翻译最危险的不是语法，而是把"逻辑值"当"显示文本"改掉。逐类核查结果：

| 风险类 | 检查方式 | 结果 |
|---|---|---|
| 中文进入比较 / `includes` / `case` | 正则扫描全部 JS 与内联脚本 | **0 处** |
| 中文进入选择器 / `getAttribute` | 扫描 `querySelector`、`[title=` | **0 处** |
| 中文进入请求体 / 参数 | 扫描 `JSON.stringify`、`URLSearchParams`、`append()` | **0 处** |
| 下拉选项值被误改 | 检查 `<option value=…>` 与文本分离 | 值均独立，如 `value="writeback"` |
| 设备直通 / 功能标志 | 检查 `path`、`key` 字段 | 仅改 `label`/`desc`，`path`（API 实值）未动 |
| 中英拼接残句 | 扫描"中文后接 3+ 英文单词" | **0 处** |
| 后端耦合 | 检查 `app.py` 是否引用被改的显示串 | 均无引用 |

### 四、单元测试（不需要 Proxmox，测试全为 Mock）

`python3 -m pytest -o addopts="" -q tests/`：

| | 基线 `64bb45d` | 汉化后 |
|---|---|---|
| 通过 | 287 | **287** |
| 失败 | 192 | **192** |
| 失败用例集合 | — | **逐条完全相同（diff 为空）** |

**注意**：上游这 192 个失败是**既有问题**，与本汉化无关。成因是该套件在当前环境
下大量接口返回 302（`before_request` 因 `config_file_exists` 为假而重定向到
`/connect`），属测试夹具与运行环境的既有不匹配。补 `data/config.toml` 亦未改变，
说明不是配置缺失单因所致。**这些用例本身没有真正执行到业务逻辑，
因此它们既不能证明我改坏了什么，也不能证明我改对了什么**——真正的信号来自上面
第二节的运行时渲染对照。


### 五、真实 Proxmox VE 环境验证（PVE 9.2.31）

在真机（单节点，PVE 9.2.31 / Debian 13）上同时运行**上游原版**与**汉化版**两个实例，
连接同一台 PVE，逐页、逐接口、逐 DOM 元素对照。全程只读，未对 PVE 做任何写操作。

| 项目 | 结果 |
|---|---|
| 页面 | 13/13 状态码、标签数、id 集合、class 集合 **与原版逐页相同** |
| 只读 API | 归一化易变字段（`avail`/`used`）与 `content` 枚举顺序后 **15/15 响应等价** |
| 可见文本 | 中文 10 → 149~848 字/页 |
| 布局 | 13 页均无横向溢出，与原版一致 |

API 对照中出现的 5 处"不一致"已逐一归因：3 处是容量数值实时变化、1 处是 PVE 返回的
`content` 枚举顺序不同、1 处是 404 错误页本身被汉化——**均非功能差异**。

### 六、浏览器运行时验证（Chromium 实跑）

`python3 i18n/browser_check.py <基线端口> <汉化端口>` 用真实浏览器加载每个页面，
采集控制台错误、未捕获异常、失败请求，以及 JS 执行后的可见文本。

| | 基线 `64bb45d` | 汉化后 |
|---|---|---|
| 控制台错误 | 0 | **0** |
| 页面异常 | 0 | **0** |
| 横向溢出 | 无 | **无** |

这一项补上了此前"只做语法检查、没在浏览器里真跑"的缺口。

### 七、真机验证中发现并修复的两个缺陷

静态检查（编译通过、标签计数一致）**没有**发现这两个问题，是真实渲染 + 截图才暴露的：

1. **`apply.py` 的 `SCRIPT_RE` 用了两个捕获组**。`re.split()` 会把内层 `(script|style)`
   也当作独立片段返回，于是每个内联 `<script>` 块后面被插入一个裸文本 `script`——
   18 个模板受影响，页面顶部可见 `scriptscriptscript…`。
   **它只增加纯文本、不增加标签，所以"标签数 / id / class 对照"完全看不出来。**
   修复：正则合并为单个捕获组。
2. **`extract.py` 把所有单词字符串当标识符丢弃**（`^[A-Za-z_$][\w$]*$`），
   导致仪表盘统计卡 `Containers` / `Templates` / `Running` / `Stopped` / `Nodes`
   仍是英文，而相邻的「虚拟机」已是中文。修复：只过滤小写开头的单词，大写开头保留，
   新增 `dict/html_labels.json`。

另补齐 19 个模板的 `{% block title %}`（浏览器标签页标题，藏在 Jinja 块内被漏掉）。

## 上游更新后如何重套

```bash
git fetch upstream
git merge upstream/main          # 或 rebase
python3 i18n/apply.py            # 重新套用词典；幂等，已翻译处不会重复处理
python3 i18n/apply.py --check    # 查看本次新增了多少待译文案
```

`apply.py --check` 会打印各分桶的词典命中率。命中率下降说明上游加了新文案，
按提示把新字符串补进对应 `dict/*.json` 即可——**不需要**再碰任何模板文件。

## 已知限制（哪些**没有**被验证）

必须明确区分"已验证"与"未验证"：

| 项目 | 状态 | 原因 |
|---|---|---|
| Jinja 模板编译与渲染 | ✅ 已验证 | 静态 23 个模板全编译；真机 13 个页面结构与原版逐页一致 |
| JS 语法 | ✅ 已验证 | `node --check` 全部通过 |
| JS 运行时行为 | ✅ 已验证 | Chromium 实跑 13 页，两侧均 0 控制台错误 / 0 页面异常 |
| 翻译未污染逻辑值 | ✅ 已验证 | 七类风险逐项扫描，均为 0 |
| 只读 API 数据链路 | ✅ 已验证 | 15/15 接口响应等价（归一化易变字段后） |
| 真实部署 | ✅ 已完成 | systemd + venv 部署于 PVE 9.2.31，开机自启 |
| Python 单元测试 | ⚠️ 部分 | 287 通过 / 192 既有失败，两侧逐条一致；失败用例未触及业务逻辑 |
| 真实数据驱动的表格行文案 | ⚠️ 部分 | 节点/存储等真实数据已渲染，但该机 0 台虚拟机，VM 列表单元格未被填充 |
| **VM 详情 / 编辑 / 克隆 / 快照页面** | ❌ **未验证** | 环境中没有虚拟机 |
| **VNC / 串口控制台** | ❌ **未验证** | 需要真实虚拟机才能开 vncproxy |

因此本汉化的准确表述是：**服务端渲染、浏览器运行时、只读 API 链路均已对照基线验证；
未验证的仅剩依赖"存在虚拟机"的功能路径（VM 详情类页面与控制台）。**

其余限制：

- `app.py` 的后端消息（flash、`jsonify` 的 error/message）**保持英文**。
  这样做是有意的：`tests/` 中有 `assertIn("Missing iso_image parameter", ...)`
  一类断言锁定英文原文，翻译会破坏测试，且会降低排错时可搜索性。
- 少数动态拼接串（如内存显示 `GB/MB/Unknown` 的复合片段）因涉及布局空白，
  保留了英文。
- 技术术语按 Proxmox 中文习惯保留英文：VM→虚拟机、Container→容器、
  Guest→客户机、Node→节点、Snippet→片段、Job→作业；`cloud-init`、`Bond`、
  `ZFS`、`Ceph`、`idmap`、`writeback` 等保持原文。
